# CV Worker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Python worker that turns staged footage into one contract-valid `DisposalEvent` per item that entered a bin, posts it to `POST /api/events`, and serves an annotated stream for the Live scene.

**Architecture:** A frame source feeds a tracker (YOLO + ByteTrack, people dropped). When a track disappears, an entry check scores each bin region from the track's path; if one bin wins, the best crop is identified against reference embeddings enrolled from the demo camera, and an event with a deterministic ID is validated against the contract JSON Schema and posted, or kept in an outbox if the API is down. Every ML component sits behind a small protocol, so the pipeline is tested with fakes and no model downloads.

**Tech Stack:** Python 3.12 via uv, ultralytics 8.4 (YOLO11n + ByteTrack), OpenCV, OpenAI CLIP ViT-B/32 (`clip` package from GitHub), jsonschema, pytest. Standard-library `urllib` and `http.server` for HTTP (no web framework).

**Spec:** `worker/AGENTS.md`, `contracts/README.md` (§1 DisposalEvent, §4 worker stream, §6 cross-area rules), root `AGENTS.md`.

## Global Constraints

- Only `worker/` is edited (E's area). Contract changes go through `contracts/` in a separate PR. **No commits without Eymen's go-ahead.** Commit identity is repo-local `Eymen <eymenfaruk479@gmail.com>`.
- `event_id` = `"evt_" + sha256("{camera_id}|{clip_id}|{track_id}|{bin_id}")[:16]`, with `track_id` a Python `int` (reject floats). Reprocessing a clip must reproduce the same IDs.
- Every event validates against `contracts/disposal-event.schema.json` before it leaves the worker; serialize with `json.dumps(..., allow_nan=False)`.
- `occurred_at` = clip start wall-clock time + `clip_offset_s`, ISO-8601 UTC with `Z` and milliseconds. `source.mode = "recorded"` for clips.
- The worker never applies confidence thresholds to items or businesses and never sends correctness (contract §6). It sends `catalog_item_id: null` only when it has no candidate, and then `confidence: null`. Business is `{null, null, []}` until logo reading exists.
- People are never stored or identified: the `person` class is dropped before tracking output is used, and evidence crops contain only the item box.
- Env vars: `API_BASE_URL`, `WORKER_INGEST_TOKEN`, `WORKER_PORT` (default 8765).
- `throw_score()` in `entry.py` is **Eymen's code** (learning task). The plan writes its tests and a stub; the implementer does not fill in its body.

## Review Focus

1. **The API is down or slow mid-demo:** events must not vanish. They go to `outbox.jsonl` and `flush` resends them later; duplicates are harmless because IDs are deterministic. (Task 4 test.)
2. **The same clip is run twice:** identical event IDs and identical outbox content. (Task 5 test.)
3. **An item is held near a bin and carried away:** no event. (Task 2 test cases; Eymen's `throw_score` must pass them.)
4. **A short occlusion** (track missing for fewer than `gone_after_frames` frames): no early finalization and no second event. (Task 5 test.)
5. **A video resolution different from the one the regions were drawn on:** normalized regions scale to any frame size, and evidence boxes partly outside the frame are clamped, not crashed on. (Task 1 and Task 5 tests.)

### Task 4: Event sink with outbox

**Files:**
- Create: `worker/recyclone_worker/client.py`
- Test: `worker/tests/test_client.py`

**Interfaces:**
- Produces:
  - `EventSink` protocol: `send(event: dict) -> str`, returning `"created" | "duplicate" | "queued"`.
  - `HttpSink(api_base: str, token: str, outbox: Path, timeout_s: float = 3.0)`. It POSTs `{api_base}/api/events` with `Authorization: Bearer {token}`. A network error, a timeout, or HTTP 5xx appends the event to the outbox and returns `"queued"`.   - `flush_outbox(sink: HttpSink) -> tuple[int, int]` returns `(sent, still_queued)` and rewrites the outbox with only the failures.
  - `MemorySink` for tests and dry runs.
